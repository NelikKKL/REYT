# yt-dlp GUI (Rust, egui, тёмная тема)

Портативное приложение для скачивания видео/аудио через `yt-dlp`.
Одно окно, тёмный интерфейс, глубокая настройка формата, поддержка плейлистов,
выбор папки, и (после сборки) — один самодостаточный `.exe`, внутри которого
уже лежат `yt-dlp` и `ffmpeg` (извлекаются во внутреннюю папку приложения при
первом запуске).

## Возможности

- Ссылка на видео **или** на плейлист — плейлист скачивается целиком,
  режимом можно управлять (авто / всегда весь плейлист / только одно видео),
  можно ограничить диапазон элементов (`1-10,15`).
- Выбор папки загрузки через системный диалог.
- Формат видео: контейнер (MP4/MKV/WebM/авто), разрешение (до 4K, либо
  "минимальное" для экономии трафика).
- Формат аудио: MP3/M4A/Opus/WAV/FLAC/оригинал, режим "только аудио".
- Язык звуковой дорожки (код `ru`, `en` и т.д. — работает для роликов
  с несколькими аудиодорожками).
- Встраивание обложки, метаданных, глав, субтитров (с выбором языка).
- Ограничение скорости скачивания.
- Шаблон имени файла и произвольные доп. флаги yt-dlp — для тонкой настройки
  сверх того, что есть в UI.
- Живой прогресс-бар, скорость, ETA, номер элемента плейлиста, лог вывода
  yt-dlp.
- Кнопка отмены загрузки в любой момент.

## Структура проекта

```
yt-dlp-gui/
├─ Cargo.toml
├─ build.rs            # встраивает иконку .ico в exe на Windows (опционально)
├─ bin/                 # СЮДА положить настоящие yt-dlp и ffmpeg перед сборкой
│  ├─ yt-dlp.exe         (Windows)
│  ├─ ffmpeg.exe         (Windows)
│  ├─ yt-dlp             (Linux/macOS)
│  └─ ffmpeg             (Linux/macOS)
├─ assets/
│  └─ icon.ico          # опционально, иконка приложения
└─ src/
   ├─ main.rs           # точка входа, настройка окна
   ├─ app.rs             # весь UI (egui), тёмная тема
   ├─ settings.rs        # структура настроек + генерация аргументов yt-dlp
   └─ downloader.rs      # встраивание бинарников, запуск процесса, парсинг прогресса
```

## Как собрать

### 1. Установите Rust
https://rustup.rs (стабильная toolchain, `stable-x86_64-pc-windows-msvc` для
Windows-сборки).

### 2. Положите реальные бинарники в `bin/`

Файлы в `bin/` сейчас — **текстовые заглушки**, приложение с ними не
запустится. Их нужно заменить:

- `bin/yt-dlp.exe` — скачайте с
  https://github.com/yt-dlp/yt-dlp/releases (файл `yt-dlp.exe`).
- `bin/ffmpeg.exe` — скачайте статическую сборку ffmpeg для Windows, например
  с https://www.gyan.dev/ffmpeg/builds/ (essentials build, файл `ffmpeg.exe`
  из папки `bin`).
- Для Linux/macOS аналогично положите бинарники `yt-dlp` и `ffmpeg` (без
  расширения) — можно взять из официальных релизов/пакетных менеджеров
  (`pip install yt-dlp` даёт не то, нужен именно standalone-бинарник, либо
  `brew install ffmpeg` и скопировать бинарник).

Размер финального exe будет заметным (~80–150 МБ) — это ожидаемо, так как
внутри буквально лежат yt-dlp и ffmpeg.

> Важно про лицензии: ffmpeg распространяется под LGPL/GPL в зависимости от
> сборки. Если планируете публично распространять готовый exe, используйте
> LGPL-сборку ffmpeg (без `--enable-gpl`) или проверьте условия лицензии
> используемой сборки — это не юридическая консультация, а просто напоминание
> свериться с лицензией перед распространением.

### 3. Соберите проект

```bash
cd yt-dlp-gui
cargo build --release
```

Готовый файл появится в `target/release/yt-dlp-gui.exe` (Windows) или
`target/release/yt-dlp-gui` (Linux/macOS). Это и есть тот самый один
переносной exe — можно копировать на другой компьютер и запускать без
установки Python/yt-dlp/ffmpeg отдельно (они извлекутся автоматически при
первом запуске в `%LOCALAPPDATA%\yt-dlp-gui\bin` на Windows или аналогичную
папку на других ОС).

### 4. (опционально) Иконка

Положите `.ico`-файл в `assets/icon.ico` — `build.rs` подхватит его
автоматически на Windows.

## Сборка через GitHub Actions (не нужно ничего скачивать руками)

В репозитории есть `.github/workflows/build.yml`. Он сам:

1. Скачивает свежий `yt-dlp.exe`/`yt-dlp` с официальных релизов
   [yt-dlp/yt-dlp](https://github.com/yt-dlp/yt-dlp/releases).
2. Скачивает статическую сборку `ffmpeg` (Windows/Linux — из
   [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds), LGPL-вариант;
   macOS — через `brew install ffmpeg` на раннере).
3. Кладёт их в `bin/`, собирает `cargo build --release` под Windows, Linux и
   macOS.
4. Загружает готовые бинарники как артефакты сборки (вкладка **Actions** →
   выбранный запуск → **Artifacts**).
5. Если запуск случился из-за пуша git-тега вида `v1.0.0`, дополнительно
   создаёт GitHub Release и прикрепляет к нему все три бинарника.

### Как запустить

- **Вручную**: вкладка **Actions** → workflow **Build yt-dlp GUI** → **Run
  workflow**.
- **Автоматически**: при пуше в ветку `main` (соберёт и оставит артефакты) или
  при пуше тега:

  ```bash
  git tag v1.0.0
  git push origin v1.0.0
  ```

  — тогда после сборки во вкладке **Releases** появится готовый релиз с
  `yt-dlp-gui-windows-x64`, `yt-dlp-gui-linux-x64`, `yt-dlp-gui-macos-x64`.

> Имена файлов в релизах BtbN/FFmpeg-Builds иногда меняются (например,
> добавляется/убирается суффикс с версией ffmpeg). Если шаг "Download ffmpeg"
> начнёт падать с 404, откройте
> https://github.com/BtbN/FFmpeg-Builds/releases/tag/latest и поправьте имя
> архива в `FFMPEG_RELEASE_URL`/шаге скачивания в `build.yml`.


## Как это работает внутри

- `downloader::ensure_binaries_extracted()` при старте программы копирует
  встроенные (через `include_bytes!`) `yt-dlp`/`ffmpeg` в локальную папку
  данных приложения (по SHA-256 хэшу — перезаписывает только если файл
  изменился, например после обновления версии программы).
- `settings::DownloadSettings::build_args()` превращает выбранные в UI опции
  в реальные аргументы командной строки yt-dlp (`-f`, `--embed-thumbnail`,
  `--merge-output-format`, `--sub-langs` и т.д.).
- `downloader::spawn_download()` запускает `yt-dlp` как дочерний процесс с
  перенаправленным `stdout`/`stderr`, парсит строки прогресса регулярным
  выражением и шлёт события (`Progress`, `Log`, `Finished`) в UI-поток через
  `std::sync::mpsc`.
- `app.rs` — стандартный `eframe::App`, тёмная палитра задаётся через
  `egui::Visuals` (скруглённые углы, акцентный синий цвет, приглушённый фон).

## Обновление yt-dlp/ffmpeg в будущем

Просто замените файлы в `bin/` на новые версии и пересоберите проект —
хэш изменится, и при следующем запуске у пользователей автоматически
перезапишутся закэшированные версии.

## Возможные доработки

- Очередь из нескольких ссылок для пакетной загрузки.
- Автообновление встроенного yt-dlp без пересборки exe (скачивание новой
  версии с GitHub при старте — потребует доступа в интернет и подписи
  файлов).
- Сохранение последних использованных настроек между запусками
  (`eframe` уже подключён с фичей `persistence` — можно сериализовать
  `DownloadSettings` через `serde` в `App::save`).
